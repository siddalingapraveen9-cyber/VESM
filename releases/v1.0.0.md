# Release Notes — v1.0.0

**Release date:** See `CHANGELOG.md` for the dated entry corresponding to this
release.
**Status:** Public release.

## What v1.0.0 Contains

VESM v1.0.0 is a complete, documentation-first engineering methodology, organized
into five parts:

- **Constitution** (`constitution/`, 8 documents) — what VESM is, why it exists,
  its permanent principles, terminology, and the policies governing how it is
  governed and how it changes: `constitution/VESM_CONSTITUTION.md`,
  `constitution/ENGINEERING_PHILOSOPHY.md`, `constitution/VISION_AND_MISSION.md`,
  `constitution/CORE_PRINCIPLES.md`, `constitution/TERMINOLOGY.md`,
  `constitution/GOVERNANCE.md`, `constitution/VERSION_POLICY.md`,
  `constitution/CHANGE_POLICY.md`.
- **Core Standards** (`core/`, 4 documents) — the mandatory methodology every VESM
  project follows: `core/VVBM.md` (a ten-stage execution cycle), `core/VQS.md`
  (eight quality dimensions), `core/GS99.999.md` (eight engineering-discipline
  principles), and `core/GIT_STANDARD.md` (ten vendor-neutral version-control
  topics).
- **Engineering Toolkit** (`templates/` and `checklists/`, 9 documents) — the
  working documents and objectively-verifiable checklists used to execute the Core
  Standards on a real project.
- **AI Engineering Standard** (`ai_standard/`, 2 documents) — vendor-neutral
  behavioral requirements for any AI assistant participating in a VESM project, and
  the diagnostic workflow used during Investigation.
- **Examples & Case Studies** (`examples/` and `case_studies/`, 3 documents) — a
  complete worked walkthrough of the methodology, a reusable case-study format, and
  a filled reference case study.

Root-level governance documents (`README.md`, `LICENSE`, `CHANGELOG.md`,
`CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `ROADMAP.md`, `VERSION.md`) complete the
repository.

## What Is Deliberately Not in v1.0.0

`advanced/`, `certification/`, and `reference/` — Advanced Rules, formal
certification criteria, and a repository-wide glossary/FAQ — are not part of this
release. This was a deliberate scope decision, not an oversight: applying VVBM
Stage 1 (Mission Freeze) and `constitution/CORE_PRINCIPLES.md` Principle 8
(Completion over endless expansion) to VESM's own development, none of the three are
required for an engineer to use the methodology today. They are recorded as
candidates in `ROADMAP.md`.

## Self-Verification

VESM v1.0.0 was itself developed under VVBM: each part above was built as its own
Mission Freeze → Architecture → Implementation → Verification cycle, with an
independent consistency and cross-reference audit performed before each part was
considered complete, and a final repository-wide audit performed before this
release (see `CHANGELOG.md` for the dated record of each pass). No document in this
release contains a placeholder, a "coming soon," or an unresolved cross-reference.

## Known Limitations at Release Time

- Compliance with VESM is currently self-assessed, via the Engineering Toolkit's
  templates and checklists — no third-party certification process exists yet (see
  `ROADMAP.md`).
- The methodology has one complete worked example and one reference case study;
  broader real-world validation across more project types will accumulate over
  time, per `case_studies/CASE_STUDY_TEMPLATE.md`.
- No Advanced Rules exist yet; every requirement across the four Core Standards
  currently applies at full weight regardless of project size.
